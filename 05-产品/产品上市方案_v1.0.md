## 三、跨平台上市部署策略

### 3.1 双平台发布节奏

```
Phase A: 内部测试（Alpha）
├── 时间: T-14 天（上市前2周）
├── 范围: 团队内部 + 种子用户（20人）
├── 平台: iOS TestFlight + Android 内部测试轨道
├── 目标: 发现阻断性 Bug，验证核心流程
└── 出口标准: 0 P0 Bug，核心流程通过率 > 95%

Phase B: 公测（Beta）
├── 时间: T-7 天（上市前1周）
├── 范围: 早期用户（100-200人）
├── 平台: iOS TestFlight + Android 公开测试
├── 目标: 收集用户反馈，验证留存指标
└── 出口标准: 次日留存 > 40%，崩溃率 < 0.5%

Phase C: 正式上架（GA）
├── 时间: T-Day
├── 平台: Apple App Store + 华为/小米/OPPO/vivo/应用宝
├── 目标: 全量用户可用
└── 监控: 实时崩溃监控、用户反馈、服务器负载

Phase D: 迭代优化（Post-Launch）
├── 时间: T+7 天 → T+30 天
├── 目标: 修复反馈问题，优化转化率
└── 重点: 用户反馈闭环、A/B 测试、性能监控
```

### 3.2 iOS 上架流程

| 步骤 | 任务 | 预计时间 | 依赖 |
|------|------|---------|------|
| 1 | 注册 Apple Developer Program（$99/年） | 1-2天 | 公司营业执照 |
| 2 | 配置 App ID + 证书 + 描述文件 | 1天 | Apple Developer 账号 |
| 3 | 配置 fluwx 微信登录 URL Schemes | 1天 | 微信开放平台审核通过 |
| 4 | 构建 Release 版本（Archive） | 半天 | 代码签名配置 |
| 5 | 上传 App Store Connect（TestFlight） | 半天 | Release 构建 |
| 6 | 填写 App Store 元数据（标题/描述/截图） | 1天 | 运营文案 + 截图 |
| 7 | 提交审核（App Store Review） | 1-7天 | 元数据完整 |
| 8 | 审核通过后发布 | 即时 | 审核通过 |

**iOS 审核风险点**:
- 儿童类 App 需额外注意隐私保护（COPPA 合规）
- 微信登录需说明账号注销流程
- 无账号系统或使用 Apple Sign In（如用第三方登录需同时提供 Apple 登录）
- 内购必须使用 Apple In-App Purchase（如后续添加付费功能）

| 内容版权纠纷（AI插画） | 低 | 中 | 🟡 中 | 确认AI生成版权归属；保留创作记录；用户协议免责 | 运营 |

| 竞品同期发布 | 低 | 低 | 🟢 低 | 差异化定位（微信生态+游戏化）；快速迭代 | Team Lead |

### 6.2 应急预案

**场景1: 微信登录审核不通过**
- 备用方案: 手机号验证码登录（已开发完成）
- 切换方式: 配置文件切换 `authMode: 'sms'`
- 恢复时间: < 2小时

**场景2: 生产服务器故障**
- 回滚方案: 上一版本 Docker 镜像一键回滚
- 切换方式: `pm2 deploy production revert`
- 恢复时间: < 15分钟

**场景3: 严重 Bug 发现（上架后）**
- 热修复: Flutter Code Push（或强制更新）
- 降级: 关闭受影响功能开关
- 恢复时间: Code Push < 30分钟；强制更新 < 24小时
